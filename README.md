# go-auction-clearing

用于承载多单位竞价与成交管理相关的 Go 服务代码。

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 交割批次与保证金结算

在清算成交与结算版本更正之上,服务提供成交后的交割批次管理与保证金结算。

### 核心流程

- `RegisterTrade` / `ClearTrade`:登记撮合成交并完成清算。
- `CorrectTrade`:更正成交数量/价格,结算版本 `SettlementVersion` 递增。
- `CreateBatch`:清算完成后创建交割批次,冻结成交清单、成交数量、
  价格版本与截止时间。一笔成交只能属于一个未完成批次;已交割完成的
  成交不能再次加入新批次。
- `ConfirmDelivery`:按成交逐笔登记实际交割数量与保证金结果。
- `CancelBatchItem` / `CloseBatch`:取消批次内成交 / 关闭批次。
- `GetBatchView`:查询批次状态、每笔成交的计划/已交割/剩余数量、
  保证金处理结果以及更正关联(冻结版本 vs 当前版本)。

### 关键语义

- **部分交割**:每次确认只能减少剩余数量,超量返回 `ErrOverDelivery`;
  批次只有在所有成交完成或被明确取消后才能 `CloseBatch`。
- **并发裁决**:交割确认、成交更正、批次关闭在同一把锁内按顺序裁决。
  更正先生效时,旧批次冻结版本失效,继续确认返回 `ErrVersionConflict`;
  批次先关闭时,迟到确认返回 `ErrBatchClosed`。确认与保证金记录在同一
  临界区落库,不会产生孤立的保证金记录。
- **幂等**:每个交割确认携带外部操作号 `opID`。同号同内容重放返回原
  确认结果;成交、数量或保证金内容变化返回 `ErrIdempotencyConflict`。
  失败重试不会重复扣减数量或重复生成交割记录。
- **持久化**:所有状态变更后写入 JSON 快照(临时文件 + rename),
  `LoadStore` 可在重启后恢复成交、批次、确认记录与幂等表。
